# Technical Specification: Full System Integration (Real-World)

**Goal:** Bridge every UI feature to the real `haworks` domain services and infrastructure nodes. No simulations. The UI is a pure telemetry window into a live .NET 9 cluster.

---

## 1. Core Framework: The "Infrastructure Observer"
We will use a decoupled observation pattern to keep the domain clean while piping telemetry to the UI.

### 1.1 The SignalR Gateway (Api Project)
*   **Hub:** `DemoHub.cs` manages SignalR groups keyed by `X-Demo-Session`.
*   **Broadcaster:** `IDemoHubNotifier` is injected into observers to send structured DTOs (`SagaStep`, `OutboxEvent`, etc.).

## 2. Feature-by-Feature Integration Plan

### 2.1 Distributed Saga (Orders & Payments)
*   **Real Service:** `Orders.API` + `Orders.Domain` (MassTransit State Machine).
*   **Integration:**
    1.  **UI Command:** `POST /api/orders` with `X-Demo-Session`.
    2.  **Observer:** Implement `IPublishObserver` and `IReceiveObserver` in the MassTransit container.
    3.  **Telemetry:** 
        *   When `OrderCreated` is consumed -> Emit `SagaStep: AwaitingStock`.
        *   When `StockReserved` is consumed -> Emit `SagaStep: AwaitingPayment`.
        *   When `PaymentCompleted` (from the real Payments service) is consumed -> Emit `SagaStep: Finalized`.
*   **Proof:** Users see the actual state machine transitions defined in your C# code.

### 2.2 Transactional Outbox (Guaranteed Delivery)
*   **Real Service:** Any service using `OutboxMessages` (e.g., `Catalog`).
*   **Integration:**
    1.  **UI Command:** Any update command (e.g., `PATCH /api/catalog/products/{id}`).
    2.  **Observer:** EF Core `SaveChangesInterceptor`.
    3.  **Telemetry:**
        *   `OnSavingChanges`: Detects new records in the `OutboxMessages` DbSet -> Emit `EventFlow: Persisted`.
        *   **Relay Hook:** In the `OutboxProcessor` background service, after a successful RabbitMQ publish -> Emit `EventFlow: Dispatched`.
*   **Proof:** Real-time visibility into the "Atomic Commit" of business data and its corresponding event.

### 2.3 Optimistic Concurrency (Postgres xmin)
*   **Real Service:** `Inventory.API` (PostgreSQL backend).
*   **Integration:**
    1.  **UI Command:** Concurrent `PUT /api/inventory/{id}` with conflicting `If-Match` headers.
    2.  **Architecture:** EF Core is configured with `.IsRowVersion()` on the `xmin` column.
    3.  **Telemetry:** Use a **Global Exception Filter**. When `DbUpdateConcurrencyException` is caught, it extracts the current vs. expected versions and pipes a `ConcurrencyConflict` event to SignalR.
*   **Proof:** A real database conflict generated by the storage engine, not a mock.

### 2.4 Resilience Pipelines (Polly v8)
*   **Real Service:** API Gateway or Service-to-Service clients.
*   **Integration:**
    1.  **UI Command:** Toggle "Faulty Service" in Chaos Engine (sets `X-Chaos-Faulty` header).
    2.  **Observer:** Configure the `ResiliencePipeline` with event hooks:
        ```csharp
        OnOpened = args => _notifier.NotifyCircuitState(args.Context, "open"),
        OnClosed = args => _notifier.NotifyCircuitState(args.Context, "closed")
        ```
    3.  **Telemetry:** The real Polly engine trips based on real 503s injected by the `ChaosMiddleware`.
*   **Proof:** Senior-level proof of high-availability strategy in action.

### 2.5 HybridCache Multi-Tiering (.NET 9)
*   **Real Service:** `Catalog.API`.
*   **Integration:**
    1.  **UI Command:** High-frequency `GET /api/products/{id}`.
    2.  **Observer:** A decorator pattern or `DiagnosticSource` listener for `Microsoft.Extensions.Caching.Hybrid`.
    3.  **Telemetry:** Capture the `Source` (L1/L2/DB) and `Duration`.
*   **Proof:** Live visual proof of .NET 9 performance gap (1ms vs 150ms).

## 3. The New "Payments" Module
A dedicated module to demo the critical path of a distributed system.

*   **Endpoint:** `POST /api/payments/process`.
*   **Pattern Demo:**
    1.  **Idempotency:** Uses `X-Idempotency-Key` + Redis to prevent double-charging.
    2.  **Transactional Outbox:** Saves the `Payment` record and the `PaymentCompleted` integration event in one transaction.
    3.  **Resilience:** Uses a Polly `Retry` + `CircuitBreaker` for the external Payment Gateway call.
*   **UI Visual:** A high-fidelity "Payment Terminal" that shows the internal technical handshake (Redis Lock -> DB Write -> Outbox Stored -> Relay Dispatch).

## 4. Technical Infrastructure Readiness

### 4.1 Deployment (Fly.io)
*   Deploy the `haworks.Api` as a Docker container.
*   Configure Fly.io **Secrets** for:
    *   `ConnectionStrings:Postgres` (Neon)
    *   `ConnectionStrings:Redis` (Upstash)
    *   `ConnectionStrings:RabbitMQ` (CloudAMQP)
    *   `Vault:Token` & `Vault:Addr`

### 4.2 Local Orchestration (.NET Aspire)
*   Update `haworks.AppHost` to include the Portfolio frontend:
    ```csharp
    builder.AddNpmApp("portfolio", "../portfolio-site")
           .WithReference(api)
           .WithEnvironment("PUBLIC_API_URL", api.GetEndpoint("https"));
    ```
